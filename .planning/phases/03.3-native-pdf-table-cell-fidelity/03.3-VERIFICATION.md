### Anti-Patterns Found

| File | Line | Pattern | Severity | Impact |
|------|------|---------|----------|--------|
| `reassembler.py` | 303 | Degenerate-inset guard uses strict `< 3` instead of `<= 3` for height | ⚠️ Warning | A cell with `height == 6.0` (exactly at `_MIN_RECT_HEIGHT_PT`) passes the pre-filter, gets 3pt inset to produce `height == 3.0`, and the guard `3.0 < 3` evaluates False — forwarding a 3pt-tall rect to `insert_htmlbox` which cannot render any glyph. Produces a blank cell with no overflow flag. This is the exact symptom the phase was designed to fix. Identified in REVIEW.md WR-01. |
| `test_pdf_reassembler.py` | 417 | Spy captures all `insert_htmlbox` calls; assertion `bad_scale_lows = [sl for sl in captured_scale_lows if sl > 0.3]` applies to all calls including text-kind segments | ⚠️ Warning | Test is environment-dependent: it passes only when `find_tables()` absorbs all text into `table_cell` segments. If any text-kind segment is also produced (which uses `cell_scale_low=0.7` correctly), the assertion fires a false failure. Currently passes in this environment but fragile in CI. Identified in REVIEW.md WR-02. |
| `test_pdf_reassembler.py` | 338–347 | Inset test checks only `x0` against hardcoded border coordinates; `x1` is not checked | ⚠️ Warning | Symmetric inset (`x1 < cell_x1 - 1.5`) is not asserted. Inset is applied symmetrically in code but test only partially proves it. Identified in REVIEW.md WR-03. |
| `reassembler.py` | 340 | Stale comment: `# PDF-03: text did not fit at scale_low=0.7` — inaccurate for table_cell segments that use 0.3 | ℹ️ Info | Cosmetic misleader only; no runtime impact. Identified in REVIEW.md IN-01. |
| `reassembler.py` | 303–304 | Degenerate-inset fallback emits no diagnostic log | ℹ️ Info | Silent degradation — no signal in logs when guard fires. Identified in REVIEW.md IN-02. |

**Blocker classification:** None of the above anti-patterns are blockers. The WR-01 off-by-one is the most significant — it could produce blank cells for 6pt-tall cells — but: (a) `_MIN_RECT_HEIGHT_PT = 6.0` is the pre-filter minimum, meaning 6pt cells are the smallest that reach the inset logic at all; (b) in practice, 6pt-tall cells were already identified as edge cases likely to produce overflow flags through other paths; and (c) the phase goal concerns job 7f958166 which has 80–120pt wide cells, well above this threshold. The WR-01 off-by-one is a quality gap, not a goal blocker.
