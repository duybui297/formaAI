# Phase 03.3: Code Review Report

**Reviewed:** 2026-05-04T08:00:00Z
**Depth:** standard
**Files Reviewed:** 2
**Status:** issues_found

## Summary

Phase 03.3 introduces two constants (`_TABLE_CELL_INSET_PT=1.5`, `_TABLE_SCALE_LOW=0.3`) and a conditional branch in Pass 3 that applies them exclusively to `table_cell` segments. The core logic — redact with the full cell rect, insert with the inset rect, use a lower scale floor — is architecturally sound and well-motivated by the RESEARCH.md bug reports.

Three defects surface at standard depth: one off-by-one in the degenerate-inset guard that causes the guard to silently pass 3pt-tall rects (which cannot render text) to `insert_htmlbox`; and two test assertion scope errors where the spy captures all `insert_htmlbox` calls but asserts constraints that only hold for `table_cell` calls — making the tests fragile in mixed-segment PDFs and likely to produce false failures in CI environments where `find_tables()` succeeds alongside regular text segments.

## Warnings

### WR-01: Off-by-one in degenerate-inset guard — 3pt insert rect escapes to `insert_htmlbox`

**File:** `backend/src/app/pipeline/pdf/reassembler.py:303`

**Issue:** The degenerate-inset guard is:
```python
if insert_rect.is_empty or insert_rect.width < 5 or insert_rect.height < 3:
    insert_rect = safe_rect  # degenerate cell — skip inset
```
`_MIN_RECT_HEIGHT_PT = 6.0` uses a strict less-than, so cells with `height == 6.0` pass the pre-active-pairs filter. After the 3pt total vertical inset (`1.5 top + 1.5 bottom`), the insert rect has `height == 3.0` exactly. `3.0 < 3` evaluates to `False`, so the guard does not trigger. A 3pt-tall rect is then forwarded to `insert_htmlbox` — a height where no glyph can render even at `scale_low=0.3`, producing a blank cell with no overflow flag. This is the exact symptom Phase 03.3 was designed to fix in the first place.

**Verified empirically:**
```python
r = pymupdf.Rect(0, 0, 20, 6)           # passes _MIN_RECT_HEIGHT_PT=6.0 check
inset = r + (1.5, 1.5, -1.5, -1.5)
# inset.height == 3.0  →  3.0 < 3 is False  →  guard does NOT trigger
```

**Fix:** Change the guard to `<=` for height:
```python
if insert_rect.is_empty or insert_rect.width < 5 or insert_rect.height <= 3:
    insert_rect = safe_rect  # degenerate cell — skip inset
```
Alternatively, raise `_MIN_RECT_HEIGHT_PT` to `7.0` so the minimum post-inset height is 4pt, or align the guard threshold to `_MIN_RECT_HEIGHT_PT - 2 * _TABLE_CELL_INSET_PT + epsilon`. The `<=` fix is the minimal surgical change.

### WR-02: Spy test assertion checks all `insert_htmlbox` calls, not just `table_cell` ones — false failures in mixed-segment PDFs

**File:** `backend/tests/pipeline/test_pdf_reassembler.py:413-420`

**Issue:** `test_table_cell_scale_low_resolves_overflow` spies on `pymupdf.Page.insert_htmlbox` and records every `scale_low` kwarg value in `captured_scale_lows`. The final assertion is:
```python
bad_scale_lows = [sl for sl in captured_scale_lows if sl > 0.3]
assert not bad_scale_lows, ...
```
This asserts that **every** `insert_htmlbox` call in the reassemble run uses `scale_low <= 0.3`. However, text-kind segments correctly use `cell_scale_low = 0.7`. If the synthetic PDF produces any text-kind segments alongside table-cell segments (e.g., `insert_text()` calls that are not fully absorbed by `find_tables()`), those calls will emit `scale_low=0.7` and the assertion fails — not because of a bug but because the spy scope is too broad.

The test currently passes only if `find_tables()` absorbs all text into `table_cell` segments, leaving no text-kind segments. This is environment-dependent and fragile.

**Fix:** Filter captured values by segment kind. The cleanest approach is to spy on the rect and match against known cell rects:
```python
# Capture (rect, scale_low) pairs
captured: list[tuple[pymupdf.Rect, float]] = []

def spy(self, rect, html, **kw):
    captured.append((pymupdf.Rect(rect), kw.get("scale_low", 0.0)))
    return real_insert(self, rect, html, **kw)

# After reassemble, filter to calls whose rect overlaps a known cell bbox
cell_rects = [table_cell_bboxes[seg.structural_position] for seg in table_segs
              if seg.structural_position in table_cell_bboxes]
table_cell_scale_lows = [sl for r, sl in captured if any(r.intersects(cr) for cr in cell_rects)]
bad = [sl for sl in table_cell_scale_lows if sl > 0.3]
assert not bad, ...
```
A simpler alternative: since the test already has `table_segs` and `translated_map` only maps those segs, assert that the minimum `scale_low` captured is `<= 0.3` (i.e., at least one table_cell call happened with the low value) rather than requiring all calls to comply.

### WR-03: Spy test for inset only checks x0 against hardcoded border coordinates — misses x1 inset and non-table rects

**File:** `backend/tests/pipeline/test_pdf_reassembler.py:338-347`

**Issue:** `test_table_cell_inset_prevents_word_adhesion` asserts that no captured rect starts (x0) exactly at a known cell-border x coordinate `[50.0, 150.0, 250.0]`. This has two gaps:

1. **x1 is not checked.** A rect could be inset on the left (`x0 > 50.0`) but still touch the right border (`x1 == 150.0`). The fix for Bug 1 applies symmetric insets, so `x1` should also be checked.

2. **Filtering is absent.** The assertion applies to all captured rects (both text-kind and table_cell-kind). In a PDF where text blocks happen to have `x0` equal to a border coordinate, the assertion would fire a false positive. Conversely, if text block rects happen not to start at those exact values, the assertion passes without actually proving the table_cell inset is applied.

**Fix:** Record whether each spy call is for a table_cell segment by inspecting the HTML content or by correlating rects to known cell bboxes, then assert symmetrically on both x0 and x1:
```python
# After reassemble, for each captured rect that overlaps a known cell bbox:
for r in captured_rects:
    for cell_x0, cell_x1 in [(50.0, 150.0), (150.0, 250.0)]:
        if abs(r.x0 - cell_x0) < 50:  # rough match to this cell column
            assert r.x0 > cell_x0 + 0.9, f"x0 not inset: {r}"
            assert r.x1 < cell_x1 - 0.9, f"x1 not inset: {r}"
```

### IN-02: Degenerate-inset fallback emits no diagnostic — silent loss of gutter

**File:** `backend/src/app/pipeline/pdf/reassembler.py:303-304`

**Issue:** When the degenerate-inset guard fires (`insert_rect.width < 5 or insert_rect.height < 3`), the code falls back to `safe_rect` without emitting a log entry or overflow flag. These cells silently receive the full-cell (no-gutter) insert treatment. In a production job with 1000+ `table_cell` segments, there is no signal that any cells degraded to no-inset mode.

**Fix:** Add a structured log line:
```python
if insert_rect.is_empty or insert_rect.width < 5 or insert_rect.height <= 3:
    insert_rect = safe_rect  # degenerate cell — skip inset
    import structlog as _sl
    _sl.get_logger().debug(
        "table_cell_inset_skipped_degenerate",
        segment_id=seg.id,
        cell_width=round(safe_rect.width, 2),
        cell_height=round(safe_rect.height, 2),
    )
```
