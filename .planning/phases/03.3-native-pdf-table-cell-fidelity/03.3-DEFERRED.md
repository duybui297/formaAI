## Defects deferred

### D-1 — Figure caption adjacent to image stays in source language

**Symptom:** page 5 of demo doc — `図1 前景画像と背景画像、前景画像のコピー＆ペーストによるデータ増強` stays JA in output PDF. Translation exists in DB and renders correctly in the review UI.

**Root cause:** caption block sits next to a figure image. `_clip_rect_away_from_images` shrinks the post-clip rect to 3.68pt wide → fails the min-rect-width guard → `image_collision` pre-check skips both Pass 1 redact and Pass 3 insert → source stays visible.

**Current behavior:** graceful — source visible (readable as JA, not blank). After commit `4ad0814` the pre-check moved into the partition stage so source is no longer destroyed.

**To resolve:** caption layout strategies, pick one or hybrid:
- Expand caption rect **vertically** (push content below) when horizontal room is squeezed by adjacent image
- Render caption on a **separate translated line BELOW** the image rect, leaving source visible above
- **Resize** the image rect to make room (last resort — preserves text fidelity at cost of visual fidelity)

**Estimated effort:** small phase (Phase 03.4 candidate). ~half-day if approach is "render translation below image rect".

### D-2 — Text formatting (color, bold, italic, underline, font family) not preserved

**Symptom:** translated PDF loses original visual formatting on most pages. Body prose that was bold in source renders plain. Italic emphasis lost. Colored text → black. Heading colors lost.

**What we DO preserve already:**
- `<b>` / `<i>` wrap via `spans_to_html()` for spans with bold/italic FLAGS (PDF text flags bit-4 / bit-1)
- `<h1>` / `<h2>` for spans whose font-size is ≥ 1.4× / 1.8× the block body size
- Font-name-suffix bold/italic detection (`.B`, `-Bold`, `-Italic`)

**What we DON'T preserve:**
- Span color (`color: rgb(...)` from PDF span colors)
- Variant fonts at body size (different font family at same size — often a stylistic variant in academic PDFs)
- Underline, strikethrough
- Specific font family (we substitute to Noto regardless)
- Bullet markers / list indentation (extracted as inline text)

**Root cause:** `spans_to_html()` in `pipeline/pdf/extractor.py` emits only `<b>`, `<i>`, `<h1>`, `<h2>` and a per-block size container — no `color:` inline style, no underline tag, no font-family preservation.

**To resolve:** extend `spans_to_html` to emit:
- `<span style="color:#rrggbb">` when span color != block-default
- `<u>` / `text-decoration: underline` from PDF underline flag (bit 2)
- Optionally map font-family to a preserved-vs-Noto-substitute decision per span

**Estimated effort:** medium phase. Test-heavy — need synthetic PDFs covering each formatting axis + a sample real academic PDF to verify multi-feature coexistence.
