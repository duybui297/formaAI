# Phase 03.2 Plan 04: Worker Passthrough Filter + BMC Paper Integration Test Summary

**One-liner:** Wired `kind='math_passthrough'` filter into translate_worker batch-pack stage so math segments bypass the LLM entirely, with identity `translated_text` set on ORM insert; added two BMC academic-paper integration tests (1 passes, 1 skips informatively).

## What Was Implemented

### Passthrough Filter in translate_worker.py (Task 1)

Four coordinated changes to `_run_translation` in `translate_worker.py`:

**1. Pre-translation split (before `pack_into_batches`):**
```python
_translatable = [s for s in segments if getattr(s, "kind", "text") != "math_passthrough"]
batches = pack_into_batches(_translatable, budget_tokens=settings.token_budget)
```
Math passthrough segments never enter the token-budget packer or the LLM call path.

**2. Pre-populate `translated_map` for passthrough segments (after map declaration):**
```python
for _seg in segments:
    if getattr(_seg, "kind", "text") == "math_passthrough":
        translated_map[_seg.id] = _seg.source_text
```
The map is seeded before `asyncio.gather` so passthrough entries are available alongside translated entries during the DB write phase.

**3. `batch_seg_groups` indexes `_translatable` (not `segments`):**
```python
batch_seg_groups.append(_translatable[offset : offset + len(batch)])
```
Crucial correctness fix: `batches` was packed from `_translatable`, so slicing must use the same list. Using `segments` here would have produced off-by-N misalignment for any job with passthrough segments.

**4. ORM insert sets `translated_text=source_text` for passthrough segments:**
```python
translated_text=seg.source_text if getattr(seg, "kind", "text") == "math_passthrough" else None,
```
DB row is immediately consistent. The reassembler independently skips passthrough segments via kind check, so the stored value is never reinserted — but having `translated_text` set (vs NULL) means the review UI can display the original glyph text without a special NULL-handling branch.

**Invariants preserved:**
- `segments_total = len(segments)` — still counts ALL segments for accurate progress display
- `orm_segments` iterates over `segments` — all segments persisted regardless of kind
- DOCX/PPTX paths unaffected — their segments all have `kind="text"` by default

### BMC Paper Integration Tests in test_pdf_roundtrip.py (Task 2)

Added two `@pytest.mark.skipif(not _BMC_FIXTURE.exists(), ...)` tests at the bottom of the file:

**`test_bmc_paper_table2_produces_cell_segments`:**
- Validates `find_tables()` cell extraction produces `kind='table_cell'` segments
- Asserts >10 table_cell segments and correct `page.N.table.T.row.R.col.C` position format
- **Result: SKIPPED** — BMC paper uses text-drawn table borders (not line-art primitives). PyMuPDF `find_tables()` requires explicit border lines (`draw_rect`/`draw_line` graphics) to detect tables. The BMC paper's Table 2 has borders rendered as PDF text/drawing commands that `find_tables()` does not recognize. Skip message is informative and actionable.

**`test_bmc_paper_page3_math_passthrough_segments`:**
- Validates that `AdvP4C4E74` font spans on page 3 produce `kind='math_passthrough'` segments
- Asserts `>=1` passthrough segment across all pages and `>=1` text segment on page 3
- **Result: PASSED** — Page 3 AdvP4C4E74 spans correctly emitted as math_passthrough. Body text (AdvTT* fonts) correctly remains as kind='text'.
