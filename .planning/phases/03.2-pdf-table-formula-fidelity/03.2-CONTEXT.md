# Phase 03.2: PDF table + formula fidelity — Context

**Gathered:** 2026-04-26
**Status:** Ready for planning
**Source:** Inline (post-3.1 UAT findings on job `932530eb`)

<domain>
## Phase Boundary

This phase closes two architectural PDF gaps that surfaced after Phase 3.1 UAT on the BMC academic-paper fixture (job `932530eb-eeda-4b0a-986a-7d32f74fa820`):

1. **Tables collapse on translation** — PyMuPDF `get_text("dict")` fuses table-row cells into one text block (e.g. `Age, years−0.0180.063 ± 0.002...` is one block on page 6 Table 2). Translating that block produces a single Vietnamese chunk that destroys columnar structure on reassembly.

2. **Math/symbol glyphs corrupt** — On page 3, span fonts like `AdvP4C4E74` carry the `¼` glyph and other symbols outside Noto coverage. They get translated and re-rendered with Noto, producing missing-glyph boxes.

Out of scope: scanned PDFs (Phase 4), DOCX/PPTX changes, math equation rerendering as raster.

</domain>

<decisions>
## Implementation Decisions

### Cell-aware table extraction
- Use `page.find_tables()` from PyMuPDF to detect table regions on each page
- For each detected table, iterate cells via `table.cells` (returns list of (r, c, x0, y0, x1, y1)) — emit ONE Segment per cell
- Cell `structural_position`: `page.{N}.table.{T}.row.{R}.col.{C}`
- Non-table blocks continue using the existing block-level extraction
- When `find_tables()` returns zero tables on a page, behavior is identical to the current pipeline (no regression)

### Math glyph passthrough
- Detect non-translatable spans by font-name pattern: anything NOT in the Noto coverage allowlist
- Allowlist: standard subset-font name prefixes used by mainstream PDFs (`Helvetica`, `Times`, `Arial`, `Calibri`, `Cambria`, `MyriadPro`, `Roboto`, `Liberation`, `DejaVu`, `Open Sans`, `Noto`, plus `AdvTT*` body subsets which contain Latin/CJK glyphs)
- Math/symbol fonts to passthrough: `AdvP*` (subset prefix often math), `CMSY*`, `CMR*`, `STIX*`, `MathFont*`, `Symbol`, anything matching `/math|symbol|glyph/i` in the font name, anything starting with `MT` (MathType)
- Passthrough behavior: emit a Segment with a flag (or special source_text marker) instructing the reassembler to NOT redact and NOT reinsert that span — the original glyphs stay visible in place
- Translator never sees passthrough segments

### Schema
- Extend `Segment` with `kind: Literal["text", "table_cell", "math_passthrough"]` field, default `"text"` for backward compat with existing DOCX/PPTX/PDF segments
- DB column for kind is optional in this PoC (in-memory only) — defer migration unless a DB read path needs it
- Worker dispatch: `kind == "math_passthrough"` → skip translation, store source_text as translated_text identity

### Reassembler
- Existing block-redact + reinsert path stays for `kind == "text"`
- For `kind == "table_cell"`: each cell has its own bbox in `structural_position` parsed segment metadata or carried via Segment field; redact + reinsert per cell rect with the per-block size wrapper introduced in 03.1 hotfix
- For `kind == "math_passthrough"`: skip both redact and reinsert; the source page region stays untouched

### Test fixtures
- Use `.data/jobs/932530eb-eeda-4b0a-986a-7d32f74fa820/source.pdf` as the integration fixture (BMC paper with Table 2 on page 6 and formulas on page 3)
- Synthetic minimal PDF for unit tests of `find_tables()` cell extraction and font-name passthrough detection

### Claude's Discretion
- Whether to store cell rect on the Segment object directly or recompute via a `pos_to_block`-style map in reassembler
- Exact regex / set for the Noto-coverage font-name allowlist (a small reasonable starter set is fine)
- Whether passthrough is signalled by `kind` field or by a sentinel `source_text` placeholder — pick whichever keeps the worker dispatch simplest

</decisions>

<specifics>
## Specific Ideas

- BMC paper page 6 Table 2 has 30+ rows; each row currently fuses 4 cells. After fix, each row produces 4 segments.
- BMC paper page 3 has 14 text blocks with mixed body fonts (`AdvTT86d47313`, `AdvTT99c4c969`) and math spans (`AdvP4C4E74` for `¼`). Body should still translate; math span should pass through.
- Page 5 Table 1 caption block has bbox width 9pt × height 215pt — rotated single-column. The existing `_MIN_RECT_WIDTH_PT = 20` guard skips it; do NOT regress that guard.

</specifics>

<deferred>
## Deferred Ideas

- Equation rerendering as raster image (would need MathML conversion or LaTeX hint extraction — out of scope for PoC)
- Per-cell font-size detection for table headers vs body (use existing `_body_font_size` for now)
- Multi-page table continuation (the find_tables API does not stitch — accept per-page tables for PoC)
- DB schema migration for `kind` column (in-memory enum suffices for PoC demo)

</deferred>
