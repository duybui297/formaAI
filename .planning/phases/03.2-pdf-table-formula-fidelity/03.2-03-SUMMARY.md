# Phase 03.2 Plan 03: Reassembler Kind-Aware Dispatch Summary

**One-liner:** Extended `reassemble_pdf` with kind-aware `active_pairs` routing — `math_passthrough` skips both passes entirely (source glyphs intact), `table_cell` recovers cell bbox via `find_tables()` re-run and uses a synthetic block dict for Pass 1/2/3 compatibility.

## What Was Implemented

### Kind-Aware Dispatch in active_pairs Loop (reassembler.py)

Inserted a `find_tables()` re-run at the start of the per-page processing block (after `pos_to_block` is built) to recover `table_cell` bboxes:

```python
table_cell_bboxes: dict[str, pymupdf.Rect] = {}
try:
    finder = page.find_tables()
    for t_idx, tbl in enumerate(finder.tables):
        for r in range(tbl.row_count):
            for c in range(tbl.col_count):
                ...
                table_cell_bboxes[pos_key] = pymupdf.Rect(cell)
except Exception as exc:
    _sl.get_logger().warning("reassembler_find_tables_failed", ...)
```

The `active_pairs` loop was extended with two new branches before the existing `kind='text'` path:

1. **`math_passthrough`**: `continue` immediately — no `pos_to_block` lookup, no redact annotation, no reinsert. The source page region is left fully intact.

2. **`table_cell`**: looks up `cell_rect` from `table_cell_bboxes`. Applies `_MIN_RECT_HEIGHT_PT` / `_MIN_RECT_WIDTH_PT` guards (with `"table_cell_rect_too_small"` reason). Creates a `synthetic_block = {"bbox": (x0, y0, x1, y1), "lines": []}` compatible with Pass 1 (`pymupdf.Rect(block["bbox"])`), Pass 3 (`_body_font_size(block)` returns 12.0pt fallback), and `_clip_rect_away_from_images`.

3. **`text` (default)**: existing `pos_to_block.get(seg.structural_position)` path — unchanged.

### Pass 1 / 2 / 3 Compatibility

No changes to any of the three passes. The `synthetic_block` dict with `"bbox"` as a 4-tuple is fully compatible:
- `pymupdf.Rect(block["bbox"])` — accepts 4-tuple, returns valid Rect
- `_body_font_size(block)` — iterates `block["lines"]`, empty list → returns 12.0pt fallback
- `_clip_rect_away_from_images(rect, image_rects)` — operates on Rect, not the dict

### Threat Mitigations Applied

| Threat ID | Mitigation |
|-----------|-----------|
| T-03.2-03-1 (DoS via malformed PDF) | `find_tables()` wrapped in `try/except`; warning logged; table_cell segments silently skipped |
| T-03.2-03-2 (degenerate bbox) | `_MIN_RECT_HEIGHT_PT` and `_MIN_RECT_WIDTH_PT` guards applied to cell rect before `active_pairs` append |
| T-03.2-03-3 (None cell) | `if cell is None: continue` in `table_cell_bboxes` recovery loop |

## Synthetic Block Compat Approach

The `synthetic_block` dict uses an empty `"lines": []` list. This means:
- `_body_font_size(block)` returns `12.0` (the fallback for empty blocks)
- Table cell text renders at 12pt — slightly larger than typical academic-paper 9-10pt body

This is explicitly acceptable per `CONTEXT.md` deferred items: "Per-cell font-size detection for table headers vs body — deferred." The 12pt fallback is documented and does not break any test.
