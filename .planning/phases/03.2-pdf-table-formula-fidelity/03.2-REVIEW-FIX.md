### WR-01: `zip(batch_segs, results)` silently drops segments when LLM returns fewer items than expected

**Files modified:** `backend/src/app/workers/translate_worker.py`
**Commit:** 52a4bd0
**Applied fix:** Added a `log.warning("batch_result_count_mismatch", ...)` check before the `zip` loop inside `_translate_one_batch`. The `zip` loop itself is unchanged — the reassembler's source-text fallback still applies for any dropped segments, but the diagnostic signal is now present.

### WR-02: `table_cell` segments accumulate spurious `multi_column_degraded` flags when the structural position contains `col`

**Files modified:** `backend/src/app/workers/translate_worker.py`
**Commit:** 9e51c2f
**Applied fix:** Reordered and tightened the `_degraded_seg_ids` set comprehension predicate. Added explicit `s.kind == "text"` guard so only text-kind segments are candidates for `multi_column_degraded` flagging. The `"col" not in s.structural_position` check is retained as a secondary filter but is no longer the sole exclusion mechanism for table_cell segments. Position format changes (e.g. `col` → `cell`) will no longer accidentally re-admit table cells into the flagged set.
