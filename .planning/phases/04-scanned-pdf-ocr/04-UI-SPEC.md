### Phase 4 semantic color additions

These additions extend the existing color vocabulary. All values sampled from Tailwind's built-in palette to stay within the paper aesthetic (no saturated neons, no dark fills).

#### Confidence chip (D-04-13)

| State | Condition | Background | Text | Border |
|-------|-----------|------------|------|--------|
| Green (high confidence) | `confidence >= 0.70` | `bg-green-50` | `text-green-700` | `border-green-300` |
| Amber (medium confidence) | `0.50 <= confidence < 0.70` | `bg-amber-50` | `text-amber-700` | `border-amber-300` |
| Red (low confidence) | `confidence < 0.50` | `bg-red-50` | `text-red-700` | `border-red-300` |

Rationale: Mirrors existing overflow badge (amber) and llm_refusal badge (red) color semantics already in FLAG_BADGE_STYLES. Green-50/green-700 is the only new hue; it is muted and consistent with the paper aesthetic.

#### Low-confidence banner (D-04-14)

| Property | Value |
|----------|-------|
| Background | `bg-amber-50` |
| Border | `border border-amber-300` (full border, not accent) |
| Text | `text-amber-900` for heading, `text-amber-800` for body |
| Icon | `lucide-react AlertTriangle` at 16px, `text-amber-600` |
| Radius | `rounded-md` (var(--radius) - 2px) |
| Padding | `px-4 py-3` (16px / 12px) |

Rationale per D-04-14: "amber border + light fill, not alarming red." Red is reserved for terminal errors; amber is the warn tier matching `overflow` and glossary-violation semantics.

#### New flag badges (D-04-24, D-04-31)

| Flag type | Label | Background | Text | Border | Left-border |
|-----------|-------|------------|------|--------|-------------|
| `figure_passthrough` | `FIGURE` | `bg-slate-50` | `text-slate-600` | `border-slate-200` | `border-l-slate-300` |
| `ocr_page_error` | `OCR ERR` | `bg-amber-50` | `text-amber-700` | `border-amber-200` | `border-l-amber-400` |

Rationale:
- `figure_passthrough` = info severity. Mirrors `multi_column_degraded` (existing slate/subdued). No alarm needed — figure pass-through is expected behavior.
- `ocr_page_error` = warn severity. Uses amber (same warn tier as overflow). Not red because the job continues; the page is skipped, not failed.

Source: D-04-24 ("info severity, subdued slate"), D-04-31 ("warn severity"), existing FLAG_CONFIG in FlagBadge.tsx.

### 1. Confidence Chip (NEW — D-04-13)

**Component:** Inline chip rendered in SegmentRow source-cell gutter. Separate from flag badges.

**Placement:** Adjacent to the existing breadcrumb badge (D-03-07), in the source-cell header area (`text-xs text-slate-400 font-mono mb-1 block` row). Render confidence chip BEFORE the breadcrumb text on the same line, separated by `gap-2`.

**Layout:**
```
[82%] Page 2 / Col 1 / Block 5
source text here…
```
The `[82%]` chip is `inline-block text-[10px] px-1.5 py-0.5 rounded border leading-tight` — identical structure to the existing InlineFlagBadge. The numeric value is `Math.round(segment.confidence * 100)` followed by `%`.

**Visibility rule:** Always visible when `segment.confidence !== null`. Never hidden behind hover or expand. If `segment.confidence === null` (non-OCR segment), chip is not rendered — zero width, no placeholder.

**Color rule:** Green/amber/red per color section above.

**Accessibility:** `aria-label="OCR confidence: 82%"` on the chip span.

### 2. Click-to-Expand Image Preview Row (NEW — D-04-11)

**Component:** Collapsible image section ABOVE the source/target cell pair within the existing SegmentRow div.

**Default state:** Collapsed — zero height, not rendered. Row height unchanged from Phase 2/3 baseline (`min-h-[48px]`).

**Auto-expand rule:** Segments where `segment.confidence !== null && segment.confidence < 0.70` are expanded by default on mount. This covers both amber (50–70%) and red (<50%) confidence tiers.

**Trigger:**
- Click anywhere on the row (already handled by `onClick={onFocus}`) AND separately, a dedicated expand toggle
- Keyboard `i` on the focused row toggles expand/collapse
- Clicking the row does NOT auto-expand — only the `i` key and the explicit expand button toggle the image panel. Click-to-focus is already wired; image expand must be a separate affordance to avoid accidental expansion.

**Expand toggle button:** `ChevronDown` / `ChevronUp` (lucide, 14px) rendered in a new 20px-wide gutter column between the seq-index column and the source cell. Same gutter style as the `w-12` seq-index cell: `flex-shrink-0 py-2 px-1 text-slate-400 select-none`. The button is `aria-expanded`, `aria-controls="image-preview-{segmentId}"`.

**Expanded state:** A `<div id="image-preview-{segmentId}">` renders above the source/target cells in the column flex column. Max-height 200px. Image is a standard `<img>` tag:
- `src`: `/api/jobs/{jobId}/pages/{pageN}.png` (static page PNG from backend)
- CSS clip via `object-fit: none` and `object-position: -{x*100}% -{y*100}%` computed from `region_bbox: [x0, y0, x1, y1]` normalized floats
- `width: 100%` of the available source-cell width, `max-height: 200px`
- `alt`: `"Page {N} image crop for segment {seqN}"`

**Image cropping technique:** Use a wrapper `<div>` with `overflow: hidden` at the desired display size. Inside, render the full page image scaled to the column width, then offset via `transform: translateX(-x0*imgW) translateY(-y0*imgH)` and clip to `(x1-x0)*imgW × (y1-y0)*imgH`. This approach uses CSS transform + overflow:hidden (no canvas, no server-side crop). The wrapper div height = `(y1-y0) * displayWidth / pageAspectRatio` — capped at 200px.

**No animation:** No CSS transition on expand/collapse. react-virtuoso handles variable row heights already (D-02-16); animation would conflict with virtuoso's measurement cycle. Snap open/close only.

**Page image URL:** The backend must serve `GET /api/jobs/{jobId}/pages/{pageN}.png`. The `pageN` value is extracted from `segment.structural_position` (pattern: `page.N.region.M` → extract N). If `structural_position` does not contain a page number, image preview is skipped.

### 3. Source Cell Double-Click to Edit (NEW — D-04-12)

**Default state:** Source cell is read-only (`select-text`, no pointer caret). Visual: `bg-slate-50`, `font-mono text-xs`, cursor default. Identical to Phase 2/3 appearance.

**Activation:** Double-click on the source cell div, OR press capital `E` when the row is focused.

**Activated state:** Source cell transforms to an editable `<Textarea>` component (shadcn/ui Textarea). Same dimensions as the read-only div — no layout shift. Textarea styling mirrors the target Textarea: `min-h-[48px] resize-none border-none shadow-none p-1 text-xs font-mono focus-visible:ring-2 focus-visible:ring-violet-500`. Font: JetBrains Mono (`var(--font-pt-mono)`).

**Value:** `segment.edited_source_text ?? segment.source_text`

**Persistence:** Debounced 500ms `PATCH /api/segments/{id}` with body `{ edited_source_text: value }`. Same debounce pattern as target edit (D-02-18). Save state indicator (Saving… / Saved checkmark) rendered below the source textarea, mirroring target cell pattern.

**Discard:** When `segment.edited_source_text !== null`, show a "Discard source edit" button (same style as existing "Discard edit" — `text-xs text-red-500 hover:text-red-700 h-6 px-1`). Clicking sends `PATCH /api/segments/{id}` with `{ edited_source_text: null }`.

**Re-translate button:** When source cell is in edited state AND `segment.edited_source_text !== null`, show a "Re-translate" button adjacent to the regenerate icon in the target cell footer. Style: `variant="ghost" size="sm" text-xs text-violet-600`. Clicking fires `POST /api/segments/{id}/regenerate` (same endpoint as existing `r` shortcut, which already uses `edited_source_text ?? source_text` per D-04-25). The button is labeled "Re-translate" (not "Regenerate") to signal it uses the corrected source.

**Keyboard:** `E` (capital) activates source edit on focused row. `e` (lowercase) remains for target edit (D-02-17 carry-forward). No conflict.

**Exit:** Pressing `Escape` in the source textarea returns to read-only state; pending debounced save fires. Tab moves focus to the target textarea.

### 4. Low-Confidence Page Banner (NEW — D-04-14)

**Placement:** Between `<ReviewPageHeader>` and `<ReviewFilterBar>` in `frontend/src/app/jobs/[id]/review/page.tsx`. Rendered only when ALL conditions are true:
1. Job state is `needs_review`
2. `job.metadata.low_confidence_pages` is a non-empty array

**Banner structure:**
```
[AlertTriangle icon] Pages 3, 7, 12 have low OCR confidence — verify before export.
```
Page numbers are rendered as inline `<button>` or `<span role="button">` elements styled as `font-semibold underline cursor-pointer text-amber-900 hover:text-amber-700`. Clicking a page number scrolls the segment table to the first segment of that page.

**Scroll-to-page behavior:** Find the first segment in `segments` array whose `structural_position` starts with `page.{N}.` (where N is the clicked page number). Call `tableRef.current?.scrollToIndex(indexOfThatSegment)`. This reuses the existing `SegmentTableHandle.scrollToIndex` API (Phase 2 D-02-16).

**Banner layout:** `flex items-start gap-3 mx-8 mb-4 px-4 py-3 rounded-md border border-amber-300 bg-amber-50`. Icon: `AlertTriangle` from lucide-react, `h-4 w-4 text-amber-600 mt-0.5 flex-shrink-0`. Text: `text-sm text-amber-800`.

**Data source:** `job.metadata.low_confidence_pages: number[]` — added to the JobSummary API response shape in Phase 4. If the field is absent or empty, banner is not rendered.

**Dismissal:** No dismiss button. Banner persists as long as the job is in `needs_review` and low-confidence pages exist. It is informational, not blocking.

### 5. Scanned PDF Override Toggle (UPDATED — D-04-17)

**Placement in UploadForm:** Rendered inline below the file drop zone, above the language selector row. Visible only after a `.pdf` file is selected (DOCX/PPTX files never show this).

**Auto-detect result display:**
When the backend returns the detection result (via upload form state after file selection OR a dedicated pre-flight API call), show:
```
Detected: scanned PDF — [change]
```
or
```
Detected: native PDF — [change]
```

The `[change]` is a small `<button type="button">` styled as an inline link: `text-xs text-violet-600 underline hover:text-violet-800 ml-1`. Clicking it cycles the `is_scanned_override` form state (null → true → false → null or boolean toggle).

**Implementation approach:** The auto-detect result (scanned vs native) is returned by a pre-flight endpoint `POST /api/detect` called after file selection (or embedded in the upload form response). Alternatively, the frontend can infer it from the file extension + name (always `.pdf`) and show a generic UI that submits `is_scanned_override: true | false | undefined` to the backend.

For simplicity: after a `.pdf` file is selected, show the toggle immediately in a `pending detection` state (`Detecting…`), then update to the detected result. The `detecting` boolean state already exists in `UploadForm.tsx` for tracked-changes detection — reuse the same pattern.

**Toggle states:**
| State | Display | `is_scanned_override` sent |
|-------|---------|---------------------------|
| Auto-detected: scanned | "Detected: scanned PDF — [change]" | `undefined` (auto) |
| User overrode to native | "Changed to: native PDF — [reset]" | `false` |
| Auto-detected: native | "Detected: native PDF — [change]" | `undefined` (auto) |
| User overrode to scanned | "Changed to: scanned PDF — [reset]" | `true` |

**Styling:** `text-xs text-slate-600` for the detection label. Render inside a `<div className="flex items-center gap-1 mt-2">`. No badge or card — just inline text to maintain form density.

**Form submission:** Append `is_scanned_override` to the FormData only when the user has explicitly overridden (`!== undefined`). Backend ignores the field when absent.

### 6. Output Download Menu (NEW — D-04-22)

**Placement:** In `<ReviewPageHeader>` component (existing), adjacent to the current "Export" button or replacing it with a dropdown.

**Trigger:** A split button or dropdown trigger labeled "Download" with a `ChevronDown` icon. Use shadcn `DropdownMenu` component (already in shadcn ui registry — no new install).

**Options:**
| Label | File | Default |
|-------|------|---------|
| Bilingual PDF (side-by-side) | `output.pdf` | YES — default selection |
| Translated PDF only | `output-translated-only.pdf` | — |
| Translated DOCX | `output.docx` | — |

**Default behavior:** Button click (not dropdown) downloads the bilingual PDF directly. Dropdown arrow reveals the other two options.

**Download action:** Each option fires `GET /api/jobs/{jobId}/download?artifact={bilingual_pdf|translated_pdf|translated_docx}`. The browser triggers a file download via `Content-Disposition: attachment` response header. No new page navigation.

**Loading state:** Download button shows spinner and is disabled while a download request is in-flight. Reset after response received (success or error).

**Copywriting:**
- Button label: "Download"
- Dropdown option 1: "Bilingual PDF"
- Dropdown option 2: "Translated PDF"
- Dropdown option 3: "Translated DOCX"

**Availability:** Download button is only enabled when job state is `done` or `needs_review` (same guard as existing export button per D-02-23).

## Density Guard

The following constraints enforce the Phase 4 critical visual contract guard: segment table density must stay within ±10% of Phase 2 baseline.

- **Collapsed row height:** `min-h-[48px]` — unchanged. Adding the confidence chip + breadcrumb badge + expand button to the source-cell gutter does NOT increase collapsed row height because they fit within the existing `py-2` padding.
- **New columns:** Zero. The expand toggle (ChevronDown) lives in the existing `w-12` seq-index column area (or a new `w-5` gutter that replaces part of it). No new `flex-[]` columns added.
- **Confidence chip + breadcrumb:** Both render in the existing `text-xs text-slate-400 font-mono mb-1 block select-none` header line inside the source cell. They add zero height when the source text is at least one line.
- **Expanded row:** react-virtuoso handles variable heights (D-02-16). Expanded rows may be 200px+ taller. This is expected and explicitly supported.
