## Warnings

### WR-01: `_clip_rect_away_from_images` misses images overlapping from the left

**File:** `backend/src/app/pipeline/pdf/reassembler.py:72`

**Issue:** The guard `img.x0 > clipped.x0 and img.x0 < clipped.x1` only clips when the image _starts inside_ the text rect horizontally. When an image's left edge is at or before the text rect's left edge (e.g. a full-width image or an image that extends left of the caption), the condition is `False` and the text rect is returned unclipped, even though `clipped.intersects(img)` is `True`. Verified empirically: `text_rect=(100,100,200,120)`, `image_rect=(50,90,180,130)` → `intersects=True` but result is unchanged.

For the predominant case (caption text left-of-image with the image to the right), the existing code is correct. Left-overlap is a less common layout (e.g. wide figures with captions in a column that shares the figure's horizontal span), but it is a case the function claims to handle.

**Fix:**
```python
def _clip_rect_away_from_images(
    rect: pymupdf.Rect,
    image_rects: list[pymupdf.Rect],
) -> pymupdf.Rect:
    clipped = pymupdf.Rect(rect)
    for img in image_rects:
        if not clipped.intersects(img):
            continue
        # Image overlaps from the right: clip right edge to image's left edge
        if img.x0 > clipped.x0:
            clipped = pymupdf.Rect(clipped.x0, clipped.y0, min(clipped.x1, img.x0), clipped.y1)
        # Image overlaps from the left: clip left edge to image's right edge
        elif img.x1 < clipped.x1:
            clipped = pymupdf.Rect(max(clipped.x0, img.x1), clipped.y0, clipped.x1, clipped.y1)
        # Image is below: clip bottom edge
        if img.y0 > clipped.y0 and img.y0 < clipped.y1:
            clipped = pymupdf.Rect(clipped.x0, clipped.y0, clipped.x1, img.y0)
    return clipped
```

The existing test `test_clip_rect_away_from_images_clips_right_edge` continues to pass. Add a companion test for the left-overlap case.

### WR-02: `add_redact_annot(fill=False)` passes wrong type — works today by accident

**File:** `backend/src/app/pipeline/pdf/reassembler.py:176`

**Issue:** `page.add_redact_annot` has signature `fill: OptSeq = None` — it expects `None` or a color sequence (e.g. `(1, 1, 1)`). The code passes `fill=False`, a `bool`. PyMuPDF's C extension treats any falsy value as "no fill" (transparent), so `False` behaves identically to `None` today. However:

1. `bool` is not `OptSeq`. If PyMuPDF updates its type check to reject non-`None` falsy values, this silently switches from transparent redaction to the default white fill, erasing PDF background graphics.
2. The intent ("transparent redaction") is obscured by the `False` value — a maintainer reading this would reasonably question why a boolean is passed to a color parameter.

Verified: `fill=False` and `fill=None` produce identical pixel output in current PyMuPDF 1.26.x.

**Fix:**
```python
# fill=None → transparent redaction (preserves background color/graphics)
page.add_redact_annot(rect, fill=None)
```

### IN-01: Inconsistent overflow flag dict schemas across append sites

**File:** `backend/src/app/pipeline/pdf/reassembler.py:155-162, 203-210, 231-236, 242-245`

**Issue:** The four `overflow_flags.append(...)` calls emit dicts with inconsistent key sets:

| Site | `overflow` | `auto_adjusted` | `scale_applied` | `reason` | `error` |
|---|---|---|---|---|---|
| rect_too_small (line 155) | True | absent | 0.0 | present | absent |
| image_collision (line 203) | True | absent | 0.0 | present | absent |
| exception (line 231) | True | absent | 0.0 | absent | present |
| spare_height < 0 (line 242) | True | absent | scale | absent | absent |
| scale < 1 (line 249) | False | True | scale | absent | absent |

The worker consumes these with `.get()` so there is no `KeyError` crash. But downstream code that iterates `overflow_flags` and expects a uniform schema (e.g. serialization, UI badge logic) will behave differently depending on which code path triggered the flag. Adding `"auto_adjusted": False` as a default to all `overflow=True` entries makes the schema uniform.

**Fix:** Add `"auto_adjusted": False` to the rect_too_small, image_collision, exception, and spare_height overflow entries so all dicts carry the same keys.

### IN-03: `pytest-cov` declared in both `[project.dependencies]` and `[project.optional-dependencies]` with conflicting version pins

**File:** `backend/pyproject.toml:22, 29`

**Issue:**
```toml
# line 22 (runtime dependencies — wrong placement):
"pytest-cov>=7.1.0",

# line 29 (test optional-dependencies):
"pytest-cov>=5.0",
```

`pytest-cov` is a test-only tool and should not be in `[project.dependencies]` (which is installed in every environment including production). It is correctly listed in `[project.optional-dependencies] test`. The runtime listing also pins a higher floor (`>=7.1.0` vs `>=5.0`), which may cause version conflicts when `uv` resolves the combined constraint set.

**Fix:** Remove `"pytest-cov>=7.1.0"` from `[project.dependencies]`. The entry in `[project.optional-dependencies] test` is sufficient.
