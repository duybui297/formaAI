# Phase 3.1 Plan 03: PDF Heading Detection Summary

One-liner: Font-size-threshold heading detection in `spans_to_html` using per-block body baseline, emitting `<h1>`/`<h2>` tags rendered visually larger by CSS rules in `fonts.py`.

## What Was Built

### `_detect_heading_level(span_font_size, body_font_size) -> int`

Threshold-based classifier:
- Returns 1 (h1) if `span / body >= 1.8`
- Returns 2 (h2) if `span / body >= 1.4`
- Returns 0 (body) otherwise
- Guards against `body_font_size <= 0` (T-03.1-05: malicious PDF with zero-size spans)

### `_body_font_size(block) -> float`

Estimates the block's body font size as the mode (most common) across all spans, rounded to 0.5pt precision. Tie-breaks to the minimum candidate so heading spans (large, fewer) never win over body spans (small, dominant).

### `spans_to_html` (updated)

Now calls `_body_font_size` once per block, then for each span calls `_detect_heading_level`. Large-font spans are wrapped in `<h1>...</h1>` or `<h2>...</h2>` instead of `<b>`. Italic still applies inside heading tags. Body-size spans continue to use the original `<b>`/`<i>` logic.

### `fonts.py` CSS (updated)

Two rules appended to the CSS string returned by `build_noto_archive_and_css`:
```css
h1 { font-size: 1.6em; font-weight: bold; margin-bottom: 0.2em; }
h2 { font-size: 1.3em; font-weight: bold; margin-bottom: 0.1em; }
```
The `em` units scale from the `* { font-size: 10pt; }` base rule, so headings render at ~16pt and ~13pt respectively via `insert_htmlbox`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `_body_font_size` tie-breaking: Counter.most_common returns first-seen on tie**

- **Found during:** GREEN phase verification
- **Issue:** In the test block (1 span at 24pt, 1 span at 12pt), both sizes appear once. `Counter.most_common(1)[0][0]` returned 24.0 (first-inserted in CPython 3.7+ dict ordering), making `body_font_size=24.0` and `24/24=1.0 < 1.4` → heading level 0. The test failed.
- **Fix:** After finding `max_count`, collect all sizes with that count and return `min(candidates)`. Body text is always the smallest and most frequent size in a block; on tie, smallest wins.
- **Files modified:** `backend/src/app/pipeline/pdf/extractor.py`
- **Commit:** 401dd1b (included in main implementation commit)
