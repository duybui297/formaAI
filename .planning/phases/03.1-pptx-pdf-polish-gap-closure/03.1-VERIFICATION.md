### Notable Implementation Detail: `_dominant_font_pt` Computed but Unused

The PPTX Plan 01 Truth #3 states: "Per-paragraph font budget uses dominant run font size to judge overflow, not shape-level char-count proxy alone."

The implementation computes `_dominant_font_pt` (line 98 of reassembler.py) but the variable is not used in the auto-fit decision path. The code comment says "reserved for future per-paragraph font-budget estimation." The char-ratio proxy still drives all outcomes.

**This is intentional and acceptable** because:
1. The ROADMAP SC1 uses "OR" — "per-paragraph font budget OR redact-and-reinsert path for high-density slides" — the shape-height guard satisfies this clause.
2. The primary false-positive cause (auto-fit fired on auto-height shapes that reflow naturally) is fixed by the shape-height guard alone.
3. The font size infrastructure (`_paragraph_dominant_font_pt`) is correctly built and wired for future use.

No override needed — the roadmap SC as written is satisfied. The plan's truth #3 was partially deferred within the plan execution itself.
