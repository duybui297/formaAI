### WR-02: `add_redact_annot(fill=False)` passes wrong type

**Files modified:** `backend/src/app/pipeline/pdf/reassembler.py`
**Commit:** 121fbbc
**Applied fix:** Changed `fill=False` to `fill=None` on the `page.add_redact_annot(rect, ...)` call (line 176). The original `False` value accidentally worked via PyMuPDF C-extension truthiness, but `fill` expects `None` or a color sequence (`OptSeq`). Using `None` is semantically correct and future-proof against PyMuPDF type-checking changes. Updated the inline comment to match.

### WR-01: `_clip_rect_away_from_images` misses images overlapping from the left

**Files modified:** `backend/src/app/pipeline/pdf/reassembler.py`, `backend/tests/pipeline/test_pdf_reassembler.py`
**Commit:** a2b1ddf
**Applied fix:** Replaced the original right-overlap guard (`img.x0 > clipped.x0 and img.x0 < clipped.x1`) with a two-branch structure:
- `if img.x0 > clipped.x0` — image starts inside the rect horizontally: clip right edge to `min(clipped.x1, img.x0)` (right-overlap case, same behavior as before)
- `elif img.x1 < clipped.x1` — image left edge is at or before the text rect's left edge but still intersects: clip left edge to `max(clipped.x0, img.x1)` (left-overlap case, previously unhandled)

The `min`/`max` guards prevent the rect from being inverted when the image fully covers the horizontal span. Also added `test_clip_rect_away_from_images_clips_left_edge` to `test_pdf_reassembler.py` covering the empirical case from the review (`text_rect=(100,100,200,120)`, `image_rect=(50,90,180,130)`), which now correctly clips `x0` to 180.
