# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: CONTEXT.md D-01..D-20, REQUIREMENTS.md UPLD/JOB/LANG sections, RESEARCH.md FEATURES + SUMMARY, phase objective prompt.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (initialize via `npx shadcn@latest init` in `frontend/`) |
| Preset | not applicable — initialize with default New York style, slate base color |
| Component library | Radix UI (via shadcn) |
| Icon library | lucide-react (bundled with shadcn default config) |
| Font | Inter (Latin + Vietnamese); Noto Sans CJK JP/SC bundled via next/font for CJK filename badge previews |

**shadcn rationale (Claude's discretion, CONTEXT.md):** Next.js 16 App Router greenfield — shadcn gives executor production-quality accessible primitives (Dialog, Progress, Badge, Select, Table, Toast) in one initialization step. Executor writes no Radix boilerplate. "New York" style variant matches the neutral-professional PoC brief.

**Note for executor:** Run `npx shadcn@latest init` in `frontend/`. When prompted, choose: style=New York, base color=Slate, CSS variables=yes. Add components as needed: `npx shadcn@latest add button badge progress dialog select table toast separator`.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tag-pair spacing inside badges |
| sm | 8px | Intra-card padding, inline button gap |
| md | 16px | Default element spacing, form field gap |
| lg | 24px | Card padding, section vertical gap |
| xl | 32px | Page content horizontal padding |
| 2xl | 48px | Major section breaks (upload zone top/bottom) |
| 3xl | 64px | Page-level vertical rhythm |

Exceptions:
- Upload drop zone minimum height: 200px (UX requirement, not a spacing token)
- Touch/click targets minimum: 48px height (accessibility — applies to all interactive controls; meets WCAG 2.5.5 enhanced and matches Material Design touch target guidance)
- Progress bar height: 8px (decorative, not a spacing token)

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Form labels, table cells, prose, status messages |
| Label | 12px | 400 (regular) | 1.4 | Badge text, helper text, metadata chips (detected language, format) |
| Heading | 20px | 600 (semibold) | 1.2 | Page titles, card section headers |
| Display | 28px | 600 (semibold) | 1.1 | App name in header only |

**Font family stack:**
```css
font-family: 'Inter', 'Noto Sans JP', 'Noto Sans SC', ui-sans-serif, system-ui, sans-serif;
```
- Inter: primary — covers Latin, Vietnamese diacritics correctly
- Noto Sans JP / SC: fallback for CJK characters in language labels and filename previews
- Load Inter via `next/font/google`; load Noto CJK subsets via `next/font/google` with `subsets: ['latin']` and `variable` mode

**Weight contract:** exactly 2 weights in use — 400 (regular) and 600 (semibold). No other weights are used anywhere in Phase 1.

## Color

Light mode only. No dark mode in Phase 1 (demo is desktop-internal, dark adds theming complexity not needed for the PoC demo).

| Role | Value | Tailwind class | Usage |
|------|-------|---------------|-------|
| Dominant (60%) | `#f8fafc` (slate-50) | `bg-slate-50` | Page background, main content area |
| Secondary (30%) | `#ffffff` (white) | `bg-white` | Cards, upload zone, table rows, nav bar |
| Accent (10%) | `#4f46e5` (indigo-600) | `bg-indigo-600` / `text-indigo-600` | Reserved elements listed below |
| Destructive | `#dc2626` (red-600) | `bg-red-600` / `text-red-600` | Terminal failure banner, failed job status badge only |

**Accent reserved for (exhaustive list — never apply to other elements):**
1. Primary CTA button ("Translate Document") — filled indigo background
2. Upload drop zone border on active drag hover
3. Active nav link underline / indicator
4. "Detected: Vietnamese" badge background (indigo-100 bg + indigo-700 text for contrast)
5. Progress bar fill while job is running (indigo-500)
6. Download button on completed job

**Semantic status colors (secondary palette — informational only, not accent):**

| State | Color | Tailwind | Applied to |
|-------|-------|----------|------------|
| Running | indigo-600 | `text-indigo-600` | "running" status badge text |
| Done / success | emerald-600 | `text-emerald-600` | "done" status badge text, download confirmation |
| Queued | amber-500 | `text-amber-500` | "queued" status badge text |
| Needs review | amber-600 | `text-amber-600` | "needs_review" status badge (Phase 2 placeholder) |
| Failed | red-600 | `text-red-600` | "failed" status badge text, error banner |
| Retry (non-alarming) | slate-500 | `text-slate-500` | Retry chip ("Retrying batch 7 (2/3)") — subdued, no red |

**D-12 explicit:** Retry chip uses slate-500 text, no background fill, no red. Red is reserved for terminal failure states only.

**Color contrast requirement:** All text on colored surfaces must meet WCAG AA (4.5:1 for body text, 3:1 for large text/UI components).

## Interaction Contracts

### Upload Drop Zone

| State | Trigger | Visual |
|-------|---------|--------|
| Idle | — | Dashed border-slate-300, cloud-upload icon (lucide), text "Drop your document here" |
| Drag-hover (valid) | `dragover` with single file | border-indigo-500, bg-indigo-50, text changes to "Release to upload" |
| Drag-hover (multi-file) | `dragover` with 2+ files | border-red-400, bg-red-50, text "One file at a time only" |
| File selected | `drop` or `change` | Shows filename chip + format badge + file size. Drop zone collapses to compact strip (40px). |
| Rejected — bad format | `drop` unsupported type | Toast: "Unsupported format. Upload a DOCX, PDF, or PPTX file." File not set. |
| Rejected — too large | `drop` >25MB | Toast: "File too large. Maximum size is 25 MB." File not set. |
| Rejected — multi-file | `drop` 2+ files | Toast: "Upload one file at a time." No state change. |

### Tracked-Changes Modal (D-13)

Triggered automatically on DOCX upload when backend detects `<w:ins>`/`<w:del>` nodes in the parse probe response.

Three `RadioGroup` options (exclusive):

| Value | Label | Description text |
|-------|-------|-----------------|
| `strip` | "Remove tracked changes before translating" | "Tracked insertions and deletions will be stripped. The final accepted text will be translated." |
| `preserve` | "Preserve and translate both versions" | "Inserted and deleted text will both be translated and kept in the output document." |
| `cancel` | "Cancel — I'll clean up the document first" | "The upload will be cancelled so you can accept or reject the changes in Word." |

Confirm button label: "Apply Selection". Cancel button closes dialog and resets file (same as `cancel` radio).

### Live Counter Animation (D-09 hybrid SSE)

- Counter value transitions smoothly with CSS `transition: all 300ms ease-out` via a `useCounterAnimation` hook
- On each SSE event, interpolate from current displayed value toward new `segments_done`
- On terminal state (done/failed), snap immediately to final value (no animation lag)
- If SSE is disconnected and polling takes over, counter still updates on each 2s poll tick

### Language Selectors

- Source language: default "Auto-detect". Grouped: "Auto-detect" as first option, then alphabetical list of qwen-mt-turbo supported languages. Priority languages pinned under a "Recommended" group: Vietnamese, English, Japanese, Chinese (Simplified), Chinese (Traditional)
- Target language: no default, required. Same grouping. Excludes "Auto-detect". Swap button enabled when source is not Auto-detect.
- Language data loaded from backend `GET /api/languages` on page mount via TanStack Query (stale-time: 24h — this list is static per model version)
