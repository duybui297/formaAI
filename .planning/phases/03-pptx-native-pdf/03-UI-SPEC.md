# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: PPTX + Native PDF.
> Generated by gsd-ui-researcher.
>
> **Scope:** This is a purely additive, backend-heavy phase. The UI surface is minimal:
> two new `FlagBadge` entries, a breadcrumb display in `SegmentRow`, and an updated
> `UploadForm` accept list. All other design decisions are inherited from Phase 2 UI-SPEC
> — do NOT re-implement or override anything not listed here.
>
> **Authoritative reference:** `.planning/phases/02-review-ux-glossary/02-UI-SPEC.md`

## Color

Inherited from Phase 2. Two new semantic flag colors added to the existing flag color
table.

**Extended flag color table (Phase 3 additions bolded):**

| Flag type | Color token | Tailwind classes | Applied to |
|-----------|-------------|-----------------|-----------|
| overflow (warning) | amber-500 | `text-amber-600 bg-amber-50 border-amber-200` | Overflow flag badge — text could not fit safely (Phase 1) |
| **overflow (auto-fit info)** | **slate-500** | **`text-slate-600 bg-slate-100 border-slate-300`** | **AUTO-FIT badge — `overflow` flag with `details.auto_adjusted === true` (M2)** |
| glossary_violation | violet-600 | `text-violet-700 bg-violet-50 border-violet-200` | Glossary violation badge (Phase 1) |
| placeholder_mismatch | orange-500 | `text-orange-700 bg-orange-50 border-orange-200` | Placeholder mismatch badge (Phase 2) |
| llm_refusal | red-500 | `text-red-700 bg-red-50 border-red-200` | LLM refusal badge (Phase 2) |
| **smartart** | **orange-500** | **`text-orange-700 bg-orange-50 border-orange-200`** | **SmartArt flag badge (Phase 3 — PPTX only)** |
| **multi_column_degraded** | **slate-500** | **`text-slate-600 bg-slate-100 border-slate-300`** | **Multi-column degraded flag badge (Phase 3 — PDF only)** |

**M2 overflow vs auto-adjusted rendering rule:**

`flag_type === "overflow"` has two semantically distinct states. `FlagBadge` MUST differentiate using `details.auto_adjusted`:

| Condition | Label | Tailwind classes | Meaning |
|-----------|-------|-----------------|---------|
| `flag_type === "overflow" && details?.auto_adjusted === true` | `AUTO-FIT` | `text-slate-600 bg-slate-100 border-slate-300` | TEXT_TO_FIT_SHAPE applied successfully (informational, not a warning) |
| `flag_type === "overflow" && !details?.auto_adjusted` | `OVERFLOW` | `text-amber-600 bg-amber-50 border-amber-200` | Text expansion too large to auto-fit safely (warning — user may need to act) |

**Left-border severity indicator** (existing SegmentRow pattern, extend to new types):

| Flag type | Left border color |
|-----------|------------------|
| smartart | `border-l-orange-500` |
| multi_column_degraded | `border-l-slate-400` |

**Reasoning for color choices:**
- `smartart` uses orange-500 — matches `placeholder_mismatch` severity tone (warning-level,
  actionable). Orange is appropriate because SmartArt translation is partially attempted
  but write-back is skipped; user must act manually. Does not clash with amber (overflow)
  or red (llm_refusal) in severity perception.
- `multi_column_degraded` uses slate-500 — informational, not an error. The content is
  still translated; reading order may be imperfect. Slate communicates "degraded but not
  broken" without alarming the user.

**No accent color changes.** The `#8B5CF6` violet accent reserved-for list from Phase 2
is unchanged.

### 2. SegmentRow.tsx — breadcrumb badge in SourceCell

**Placement:** Top of the source cell, above the source text. Small, muted, monospace.
Not a colored pill — neutral slate-400.

**Visual spec:**

```
┌─ source cell ───────────────────────────────┐
│ Slide 3 / Shape 1 / ¶2        ← breadcrumb │  text-xs text-slate-400 font-mono mb-1
│                                             │
│ This is the source text that is being       │  existing source text, text-xs font-mono
│ translated in this segment.                 │  text-[#111111]
└─────────────────────────────────────────────┘
```

**CSS:** `text-xs text-slate-400 font-mono mb-1 block select-none`

The breadcrumb text is `select-none` — it is structural metadata, not content the user
would want to copy. The source text below it remains `select-text`.

**Data source:** `segment.structural_position` — the raw position string already stored
per the Phase 1/2 segment schema. Parsed at render time via a pure helper function.

**Rendering rule:** Only render the breadcrumb if `segment.structural_position` is
non-null and non-empty. DOCX segments from Phase 1 have `structural_position` values
and SHOULD render breadcrumbs. No feature-flag needed — presence of the field drives
rendering.

### 3. formatBreadcrumb — display format contract

**Function signature:**

```ts
function formatBreadcrumb(structuralPosition: string): string
```

Single argument — the raw `structural_position` string. The function detects format
from the prefix, not from a separate `format` parameter. This avoids having to thread
`input_format` down to `SegmentRow` just for display.

**Detection rules (prefix-based):**

| Raw position prefix | Detected format |
|--------------------|----------------|
| `slide.` | PPTX |
| `page.` | PDF |
| anything else | DOCX |

**Format → display mapping:**

| Format | Raw structural_position example | Display string |
|--------|--------------------------------|----------------|
| DOCX | `body.para.3.run.0` | `body / ¶3 / run.0` |
| PPTX body | `slide.3.shape.1.tf.0.para.2` | `Slide 3 / Shape 1 / ¶2` |
| PPTX notes | `slide.3.notes.para.1` | `Slide 3 / Notes / ¶1` |
| PDF 2-col | `page.2.col.1.block.5.span.2` | `Page 2 / Col 1 / Block 5` |
| PDF degraded | `page.2.block.5.span.2` | `Page 2 / Block 5` |

**Parsing logic (by detected format):**

DOCX (`body.para.N.run.K` pattern):
- Extract paragraph index N → display as `¶{N}`
- Extract run index K → display as `run.{K}`
- Display: `body / ¶{N} / run.{K}`

PPTX notes (`slide.N.notes.para.K` pattern):
- Extract slide number N and paragraph index K
- Display: `Slide {N} / Notes / ¶{K}`

PPTX body (`slide.N.shape.M.tf.P.para.K` pattern):
- Extract slide number N, shape index M, paragraph index K
- Display: `Slide {N} / Shape {M+1} / ¶{K}` (shape displayed 1-indexed for human readability; raw index is 0-based)

PDF 2-col (`page.N.col.C.block.B.*` pattern — has `col` segment):
- Extract page N, column C, block B
- Display: `Page {N} / Col {C} / Block {B}`

PDF degraded (`page.N.block.B.*` pattern — no `col` segment):
- Extract page N, block B
- Display: `Page {N} / Block {B}`

**Fallback:** If pattern does not match any of the above, return the raw
`structural_position` string unchanged (safe default — never throw or return empty).

**Location:** Implement as a pure helper in `frontend/src/lib/formatBreadcrumb.ts`
(new file). Import into `SegmentRow.tsx`. Do NOT inline in the component.

### 4. UploadForm.tsx — accept extension list + help text

**Changes (surgical — touch only these two things):**

**A. File input `accept` attribute:**

```ts
// Before
accept=".docx,application/vnd.openxmlformats-officedocument.wordprocessingml.document"

// After
accept=".docx,.pptx,.pdf,application/vnd.openxmlformats-officedocument.wordprocessingml.document,application/vnd.openxmlformats-officedocument.presentationml.presentation,application/pdf"
```

**B. `ALLOWED_EXTS` set:**

```ts
// Before
const ALLOWED_EXTS = new Set([".docx"])

// After
const ALLOWED_EXTS = new Set([".docx", ".pptx", ".pdf"])
```

**C. Drop zone idle text** (currently `"Drop your DOCX here (PDF & PPTX coming soon)"`):

```ts
// After
"Drop your document here — DOCX, PPTX, or native PDF"
```

**D. Error message for unsupported type:**

```ts
// Before
"Unsupported file type. Phase 1 accepts .docx only."

// After
"Unsupported file type. Accepted formats: .docx, .pptx, .pdf"
```

**E. Tracked-changes modal guard** — the `detectTrackedChanges` call currently runs for
all files. For Phase 3, it should only run for `.docx` files (PPTX and PDF do not have
tracked changes in the python-docx sense). Add a format check before the detection call:

```ts
// Only detect tracked changes for DOCX
const hasTC = ext === ".docx" ? await detectTrackedChanges(f) : false
```

**No other UploadForm changes.** The form layout, glossary picker, language row, and
submit button are unchanged.

## ReviewFilterBar extension

The filter chip bar in Phase 2 has chips for: All, Overflow, Glossary violation,
Placeholder, Refusal. Phase 3 adds two chips:

| Chip | Label | Visible when |
|------|-------|-------------|
| SmartArt | "SmartArt ({n})" | n > 0 (PPTX jobs only in practice, but always check count) |
| Multi-col | "Multi-col ({n})" | n > 0 (PDF jobs only in practice) |

Chip styling: same as existing inactive chips (`bg-slate-100 text-slate-700`). Active
chip: violet-500 fill + white text (same as all other active chips). Chips are hidden
(not shown as disabled) when count is 0.

Chip insertion position: after "Refusal", before the `?` shortcuts button.
