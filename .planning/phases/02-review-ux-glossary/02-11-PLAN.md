Update `backend/src/app/api/routes/export.py` to catch `AttributeError` and generic `Exception`
in addition to `ValueError`, and return a structured JSON body instead of a plain string:

```python
from fastapi.responses import FileResponse, JSONResponse

@router.post("/jobs/{job_id}/export")
async def export_document(
    job_id: str,
    session: AsyncSession = Depends(get_session),
    settings: Settings = Depends(get_settings),
) -> FileResponse | JSONResponse:
    try:
        output_path = await export_job(session, job_id, settings.data_dir)
    except ValueError as exc:
        # Job not found or wrong state — 409 Conflict
        return JSONResponse(
            status_code=409,
            content={"code": "export_state_error", "detail": str(exc)},
        )
    except AttributeError as exc:
        # run_index / run_group_size missing on ORM model — 500 but recoverable after migration
        log.error("export_attribute_error", job_id=job_id, error=str(exc))
        return JSONResponse(
            status_code=500,
            content={"code": "export_failed", "detail": f"Export assembly error: {exc}"},
        )
    except Exception as exc:
        # Catch-all for unexpected failures (file I/O, DB error)
        log.error("export_unexpected_error", job_id=job_id, error=str(exc))
        return JSONResponse(
            status_code=500,
            content={"code": "export_failed", "detail": f"Export failed: {exc}"},
        )

    return FileResponse(
        path=output_path,
        media_type=(
            "application/vnd.openxmlformats-officedocument"
            ".wordprocessingml.document"
        ),
        filename=Path(output_path).name,
    )
```

Import `JSONResponse` from `fastapi.responses` (add to existing import line).
Keep the `FileResponse` import (still used in the success path).
The return type annotation changes to `FileResponse | JSONResponse` — this is fine for FastAPI.

Note: Do NOT use `raise HTTPException` — HTTPException produces `{"detail": ...}` but not
`{"code": ..., "detail": ...}`. The frontend needs the `code` field to distinguish error types.
JSONResponse gives us full control over the body shape.

**Before (typical pattern):**
```typescript
const res = await fetch(`/api/jobs/${jobId}/export`, { method: "POST" });
if (!res.ok) {
  setError("Export failed - Unknown error. Try again.");
```

**After:**
```typescript
const res = await fetch(`/api/jobs/${jobId}/export`, { method: "POST" });
if (!res.ok) {
  let detail = "Export failed. Try again.";
  try {
    const body = await res.json();
    if (body?.detail) {
      detail = body.detail;
    }
  } catch {
    // response was not JSON — keep generic message
  }
  setError(detail);
  return;
}
```

The key change: parse `response.json()` for `body.detail` on non-2xx status.
