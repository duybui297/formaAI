<objective>
UAT Test 3 reported two issues with keyboard shortcuts:

1. `shift+?` cannot work — the user must hold Shift to type `?` on standard keyboards
   (? is on the Shift+/ key). Pressing `shift+?` means holding Shift twice, which some
   browsers block or emit as a different event. The fix: detect `event.key === '?'` directly.
   In `react-hotkeys-hook`, this means changing the hotkey string from `"shift+/"` to `"?"`.
   Browser behavior: pressing Shift+/ emits `event.key = '?'` — no modifier needed in the
   hotkey string because the character itself encodes the shift state.

2. j/k UX feedback — user noted j/k "combination not good for UX". After review, j/k is a
   standard vim convention, already defended by prior plans (02-09 added the segmentCount guard).
   DECISION: KEEP j/k. The user's comment is noted; re-evaluation is deferred to Phase 3 UX review.
   No change to j/k binding. Update KeyboardHelpPanel to clearly label ? as the help toggle
   (was labeled "Shift+?" — update to "?").

Purpose: Fix the ? shortcut so the help panel is accessible; update help text for accuracy.
Output: useReviewKeyboard.ts detects "?" instead of "shift+/"; KeyboardHelpPanel shows "?".
</objective>

From frontend/src/hooks/useReviewKeyboard.ts (current — line 74 is the bug):
```typescript
// ?: toggle help panel (shift+/)
useHotkeys("shift+/", () => onToggleHelp(), { preventDefault: true });
```

Bug explanation:
- On standard US keyboards: ? is typed by pressing Shift + /
- The browser KeyboardEvent for this keypress: event.key = "?", event.shiftKey = true
- react-hotkeys-hook maps "shift+/" to: event.key = "/" AND event.shiftKey = true
- But pressing Shift+/ gives event.key = "?" (not "/") because the shift transforms / to ?
- Therefore "shift+/" never fires. The correct string is just "?" because the character itself
  implies the shift modifier.

Fix:
```typescript
// ?: toggle help panel — detect event.key==='?' directly (shift+/ sends '?' in all browsers)
useHotkeys("?", () => onToggleHelp(), { preventDefault: true });
```
